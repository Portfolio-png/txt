What was actually broken

Why the seeded pipelines looked empty when you opened them.

FIXED

Seeded pipelines used a status the app doesn't know

The seeder wrote status: 'published'. The Flutter enum is {draft, active, archived}, and firstWhere falls back to draft — so every seeded template parsed as a draft, sat outside the default Active filter, and failed the canRun check. Now seeds as active.

backend/server.js — 4 sites · verified by re-seeding a scratch DB

FIXED

Two templates had no factory or shop floor

dolly and assembly seeded with empty factory_id/shop_floor_id while the app opens on floor 1/1. belongsToDefaultFloor happens to treat empty as a match, so this was survivable — but it made the floor filter meaningless for half the library.

backend/server.js · buildSeedTemplates()

OPEN

Pipeline stages reference machines that don't exist

Seeded nodes carry machine: "Cutter 04", "Rack A1" — plain strings. The machines table has zero rows, so every stage opens Unassigned and no stage can resolve a real machine or die.

machines: 0 rows, 2 dependents · dies: 0 rows

OPEN

No stage binds an input or output item

Not one seeded node sets inputItem/outputItem. That is what drives item continuity, unit conversion, the process-code generator — and, since last change, whether an Assembly stage can raise a job at all. A stage with no bound output now logs a warning and raises nothing.

buildSeedTemplates() · every node in all 3 templates

OPEN

The assembly → jobs → worker path cannot complete

employees, freelancer_jobs and item_bom_lines are all empty. Even with an Assembly node firing correctly, the job it opens would carry zero tasks (the BOM loop finds nothing) and there is no worker to assign it to.

What to seed next

In FK order, so nothing is written before its parents exist.

  1. Machines and dies (L0). Seed the four machines the pipeline nodes already name — Cutter 04, Rack A1, and the weld/polish stations — plus a die master. Then change the node fixtures to carry real ids rather than loose strings.
  2. Bind every stage to an item (L1). Give each node an inputItem/outputItem pointing at a seeded item and unit. This lights up item continuity, unit conversion and process codes, and is a hard requirement for an Assembly stage to raise a job.
  3. Bills of material (L2). item_bom_lines for the assembled items, so an Assembly job arrives with real component tasks instead of an empty list.
  4. Employees (L0) and a sub-contractor. Unblocks 7 dependent tables and completes the assembly → job → worker path end to end.
  5. Then the remaining three dark domains — payroll (components → runs → payslips), procurement (requests → lines), portal (portal users → messages) — each of which is a self-contained chain once its hub table exists.
